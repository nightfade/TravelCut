# TravelCut

TravelCut 是完全在 Mac 本地运行的旅行视频高光提取工具。它不生成最终影片，而是分析整批素材，挑出值得保留的事件，按自然边界裁成独立视频，供剪映模板继续成片。

开发者或后续 AI 修改项目前，请先完整阅读 [`AGENTS.md`](AGENTS.md)。它是产品约束、架构、模型版本、验证状态和交接信息的唯一入口。

## 使用方式

1. 从 GitHub Release 下载最新的 `TravelCut-<版本>-macOS.zip`，在目标 Mac 解压，把 `TravelCut.app` 拖入“应用程序”。
2. 首次在 Finder 中右键 App 并选择“打开”。
3. 选择包含旅行视频的文件夹，再多选想保留的内容标签。默认全选，也可以只保留沿途风景、自然景观、城市街景、地标建筑、人物互动、当地美食、活动人文或动物中的部分类型。
4. 点击“自动挑选高光”。标签会同时影响快速筛选与 Qwen 深度判断，而不只是输出文件名。
5. 首次处理会联网下载约 3.15 GB 模型；以后可以离线使用。
6. 在自动创建的 `TravelCut 高光片段` 文件夹中取得结果。

当前测试包采用本地临时签名，尚未经过 Apple 公证。若要做到从网络下载后直接双击、完全不出现安全提示，需要使用 Apple Developer ID 签名并提交公证。

输出按旅行的天分文件夹，每天里按拍摄时间编号：

```text
TravelCut 高光片段/
├─ D1_0718_周五/
│  ├─ 001_0935_自然景观_山顶日出_DJI_0042.mov
│  ├─ 002_1018_人物互动_缆车合影_IMG_1847.mp4
│  └─ 003_1932_当地美食_烤串_C0013.mov
├─ D2_0719_周六/
│  └─ …
└─ selection.json
```

- 在剪映里把一整天的文件夹拖进素材库，按名称排序就是当天的时间线顺序
- 文件名依次是：当天序号、拍摄时分、主题、AI 语义标签、原文件名。主题是你选的 8 类内容之一，由 Qwen 从已选类型里挑最贴切的一个
- `D` 后面的数字按日历天计算，中间哪天没有入选片段，编号也会跳过，所以 D3 永远是旅行第三天
- 日期和时间按相机记录的时区计算，iPhone、DJI 等会把时区写进视频。没有记录时区的视频，按处理时这台 Mac 的时区计算
- 每个切片的创建时间设为它开始的那一刻，并保留原时区，按日期排序的软件也会排对
- `selection.json` 记录每段的完整源文件路径、原始时间范围、主题和所在文件夹

应用不要求预设总时长或单段时长。每段长度由事件的实际起止点决定。

## 照片整理

旅行回来几千张照片时用。选「照片整理」模式和照片的根文件夹，TravelCut 会递归查看所有子文件夹，把分组和关键字写进照片，在 Adobe Bridge 里直接看：RAW 写进旁边的 `.xmp`，JPEG、HEIC、TIFF、DNG 写进文件自己的元数据（只改元数据，像素不动，需要 `brew install exiftool`）。

它整理照片，不替你挑选。用一次 9,082 张的旅行检验，星级、美感、清晰度、人脸和 Qwen 的打分都预测不了你会留哪张：只看标星的照片会漏掉约四成你选中的，和随机差不多。所以默认不写星级，挑选留给你自己。

**它做什么**

1. 同一文件夹里连续拍的相似照片分成一组（连拍、同一场景补拍几张）。组员在拍摄时间上总是连续的，一组从第一张起不超过 90 秒。那次旅行 9,082 张分成 2,907 组
2. 标题写成「组 0042 · 第 1/5」（按拍摄时间的序号），关键字写组号和主题（`TravelCut › 组 › 组 0042`、`TravelCut › 主题 › 自然景观`），主题由 MobileCLIP 判断
3. 全黑、全白、严重失焦的照片加关键字 `TravelCut › 可能是废片 › 模糊`，不标拒绝
4. 可选打开「用 Qwen 写标签」：多张的组交给 Qwen3-VL-4B 写一句内容标签，加在标题末尾（「组 0042 · 第 1/5 · 父女共读」）并写成关键字 `TravelCut › 标签 › 父女共读`。Qwen 每组都要重新加载模型，几千张照片要好几个小时，所以默认关闭

需要星级时打开「同时写入星级」（命令行 `--stars`）：每组代表 3 星，组内接近的备选 2 星（每 4 张最多 1 张），废片标拒绝。星级只表示「每组代表」，不表示好坏，标题里的序号也改成组内排名。

**地点**

照片带 GPS 时（例如相机通过蓝牙从手机同步了位置），TravelCut 把坐标换成城市名，写成关键字 `TravelCut › 地点 › 挪威 › 特罗姆瑟`，并告诉 Qwen，让它写标签时能认出具体地标。没有 GPS 的照片，借用前后 30 分钟内最近一张带位置照片的城市；超过 30 分钟就不写。推断出的地点只写成地名关键字，不会写成 GPS 坐标，以免以后分不清哪些是真实定位。

地名查询完全离线：第一次遇到带 GPS 的照片时，下载 GeoNames 的城镇数据（约 14 MB，CC BY 4.0），之后在本机查询。城市名有中文时用中文，没有时用当地名称（如 Stranda）。推断依赖拍摄时间，几台相机的时间要和手机对准。

需要精确到景点时，打开「在线查询更精确的地点」（命令行 `--online-places`）。这会把带 GPS 照片的坐标发送给 Apple 的地理编码服务，关键字多一级地标，例如 `TravelCut › 地点 › 捷克 › 布拉格 › 查理大桥`。相距约 100 米以内的照片只查一次，结果缓存在照片文件夹的 `.travelcut-cache/` 里，重跑不再联网。Apple 限制查询频率，每分钟最多约 50 次（实测），所以 TravelCut 每 1.25 秒查一个点，1,000 个点约 21 分钟。偶尔被限流时会等 1 分钟再继续。查不到或网络不通的点保留离线城市名。没有 GPS、靠时间推断的照片只写到城市一级。默认关闭。

**在 Bridge 里怎么看**

- 按「创建日期」排序，同一组的照片挨在一起
- 在「首选项 → 缩略图」里把附加元数据设成显示标题，缩略图下就能看到组号
- 一组一组看，给你要的照片打星；用关键字面板按组、主题、地点筛选，或者先排除「可能是废片」

**安全规则**

- 不改像素：RAW 只写同名的 `.xmp`，JPEG 等格式只改元数据
- 不动你的星级和颜色标签。已经打过星的照片也会写上分组和关键字
- 旧版本写过的星级，你没改过的会清掉；打开「同时写入星级」时，已有星级或颜色标签的照片整张跳过
- 已有的 Camera Raw 调整和其他元数据原样保留
- 重复运行会更新 TravelCut 上次写的标题和关键字，你自己加的关键字保留

每次运行都会在根文件夹生成「TravelCut 照片整理报告.json」，列出每组的照片、每组代表、Qwen 的判断和每张的诊断数据。勾选「试运行」时只生成报告，不写入照片。打开「导出画面特征」时，还会导出「TravelCut 照片特征.json」（每张照片的 MobileCLIP 画面特征），用于学习个人口味的实验；打开「保存调试日志」时，会写「TravelCut 调试日志.txt」，记录分组距离、Qwen 原始输出和分析失败的原因。两个文件都在照片根目录。命令行对应 `--export-features` 和 `--debug-log`，原来的环境变量 `TRAVELCUT_EXPORT_FEATURES=1`、`TRAVELCUT_DEBUG=1` 也仍然有效。

命令行：

```bash
travelcut-cli --photos --input "/path/to/photos" [--dry-run] [--fast-only] [--themes "自然景观,人物互动"] [--export-features] [--debug-log]
```

不开 Qwen 时，9,000 张照片大约半小时到一小时。命令行用 `--fast-only` 关闭 Qwen。

每张照片的分析结果和每组的 Qwen 判断都缓存在根目录的隐藏文件夹 `.travelcut-cache/` 里，算完一张存一张。重跑时直接复用，中途停掉后再跑会从停下的地方接着来。照片按「相对路径 + 拍摄时间」识别，所以写入星级、挪动整个文件夹都不会让缓存失效；改了主题选择也只重算主题，不重新分析。分析失败的照片不进缓存。想强制全部重算，删掉这个文件夹，或者用 `TRAVELCUT_NO_CACHE=1` 启动。

## 本地分析流程

1. 读取全部素材的拍摄时间和媒体规格。
2. 检测场景变化，划分自然事件；超长连续镜头只在分析时分块，连续入选部分会重新合并。
3. 使用 MobileCLIP-S2、Apple Vision 和多帧技术指标快速排除黑屏、误拍、严重失焦及明显重复内容。
4. 使用 Apple Sound Analysis 检测笑声、欢呼、掌声、讲话、风噪等现场声音。
5. 只把初筛候选交给 Qwen3-VL-4B，结合用户选择的内容类型、多帧和声音标签判断记录价值、完整性、标签和最终起止时间。选中“沿途风景”后，不会仅因景色常见而拒绝清晰稳定的旅途记录。
6. 在整批素材中比较、去重并按拍摄时间排序。
7. 使用 AVFoundation passthrough 从原文件分别裁出高光，不创建统一画布，也不添加转场或配乐。

所有视频分析均在本机完成，不调用云端 AI API，也不消耗在线模型 token。

## 模型与硬件

- 深度模型：Qwen3-VL-4B-Instruct，Q4_K_M 量化。
- 视觉投影：Q8_0。
- 推理后端：随 App 分发的 llama.cpp Apple Silicon 版本。
- 快速层模型：Apple MobileCLIP-S2 的 Core ML 版本，从 Apple 官方 Hugging Face 仓库 `apple/coreml-mobileclip` 下载，约 199 MB。
- 首次使用共下载约 3.15 GB 模型文件，固定保存在 `~/Library/Application Support/TravelCut/Models/`。
- 最低系统：Apple Silicon Mac，macOS 14 或更新版本。
- 推荐内存：24 GB。分析候选按顺序执行，每次最多使用10帧，避免批量并发占满内存。

## 媒体保真

每段高光使用 `AVAssetExportPresetPassthrough` 导出，不统一分辨率、横竖方向或帧率，也不重新渲染画面。原始视频与音频轨、HDR信号和可由目标容器承载的元信息会保留。MTS/M2TS 等不适合作为输出容器的格式会改装入 MOV，但不会主动改变音视频编码。

`selection.json` 同时记录来源文件、原始时间范围、分辨率、帧率、编码、HDR、声音标签和 AVFoundation 可读取的源元信息，便于追溯容器未能携带的字段。

## 中断恢复与保持唤醒

- 完成整批筛选后，TravelCut 会先把入选片段写入隐藏检查点，再开始导出。
- 每成功导出一段就更新检查点。磁盘空间不足、App 退出或导出失败后，清理空间并用相同素材和标签再次运行，会跳过已经完成的分析与片段。
- 导出前会按来源文件码率和入选时长估算所需空间，并预留安全余量；不足时先停止导出，但保留筛选结果。空间容量通过多种 macOS API 交叉回退，异常的 0 或负数不会被当作真实容量。
- 筛选与导出期间会阻止 App Nap、显示器空闲睡眠和系统空闲睡眠，避免普通自动锁屏让本地模型暂停。任务结束或失败后恢复系统原有设置。
- 手动锁定屏幕、合上笔记本或公司 MDM 强制锁定不在 App 可绕过的范围内。

## 当前边界

- 通用模型不知道某个普通画面对个人的特殊纪念意义。
- 无损直通裁剪受原视频关键帧结构影响；播放器可能依赖编辑列表从准确时间开始播放。
- 当前快速质量层使用多帧 Vision 与技术指标。DOVER-Mobile 尚未纳入安装版，需要先完成 Core ML 转换和真实旅行素材基准测试，不能仅凭论文指标加入。
- MobileCLIP 权重由 Apple 以研究用途许可发布，TravelCut 不分发它，而是在首次使用时从 Apple 官方仓库下载。使用前请阅读 `Sources/TravelCutCore/Resources/Licenses/MobileCLIP-MODEL-LICENSE.txt`。

swift run --disable-sandbox travelcut-cli \
